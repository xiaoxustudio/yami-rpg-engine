refactor(element-data): migrate the tree, list and tab-bar groups, and unify dataValue

P4b batch B1 (tree list / select list / scroll bar / tab bar) plus the follow-up
work that came out of the strict-mode verification.

Tree and list group - 148 sites:
- tree-api.ts: dragging 14, selections 9, row `item` 13, hint `target` 11, by
  extending the existing TreeListElementData view (no second shape) and adding a
  `?.`-safe rowDataOrUndefined because elementDataOf(null) throws
- tree-render.ts 6, select-list-api.ts 22, scroll-bar-api.ts 21, YMTabBar.vue 49,
  and the five specs that drive them
- YMTitleBar.spec.ts is deliberately untouched: YMTitleBar.vue installs its own
  `dragging` accessor, so `expect('dragging' in el)` still asserts something real
  after the prototype accessors are gone

`dataValue` is the one field with two storage mechanisms - the select-box family
installs its own accessor (component state) while list row elements use element
data - so it now has one documented helper, `elementDataValueOf` (own property
first, else element data), used by utils/dom.ts's read, radio-proxy's member
lookup, common-list-core's findItemIndex, select-list-api's host read, the
editor's read/write helpers and useCurveWindow's setItemNames. All of them were
previously reading `el.dataValue`, which only worked because the prototype
accessor answered for both kinds.

- element-data.ts also gains P4B_STRICT=1: any real accessor use throws with the
  field name and stack (except the jsdom selector engine's internal `mode` read),
  so "did we miss a site" becomes a test run instead of a sampling exercise. The
  first run reported 807 editor + 33 ui-kit failures; after this commit the
  ui-kit suite is down to five, all of them understood: `active` on page-manager
  elements (Vue owns it, the imperative api factory uses element data - see the
  dual-storage rule), a spec fixture that Object.assigns `dataItems` onto a div,
  and Vue's patchDOMProp writing the vestigial `:filter` binding
- two spec helpers were reading element data off the element
  (command-form-registry.spec itemsOf, select-box.spec's setItemNames mock);
  both now read the same store the production code writes

Gates: ui-kit tsc 0, editor tsc strict 0, oxlint 0/0, ui-kit batch suites 14
files/152 tests, editor engine specs 5 files/80 tests - all green.
